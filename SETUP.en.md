# Setup Guide: WeChat Bridge from Zero

[中文版](SETUP.md)

Nine steps, in order, to get the WeChat bridge running from scratch. Install commands come from the plugin's official docs; the patch and scheduling come from a real working environment.

## 0. Prerequisites

- Node.js `>= 22.13.0`
- OpenClaw `>= 2026.3.22` (`>= 2026.5.12` recommended)
- A machine that stays on (Linux / macOS / WSL)

## 1. Install OpenClaw

Follow the official guide: https://docs.openclaw.ai/install

Verify:

```bash
openclaw --version
```

## 2. Install the WeChat plugin

```bash
npx -y @tencent-weixin/openclaw-weixin-cli install
```

If that fails in your environment, try:

```bash
openclaw plugins install "@tencent-weixin/openclaw-weixin"
```

## 3. Enable the plugin

```bash
openclaw config set plugins.entries.openclaw-weixin.enabled true
```

## 4. Log in with WeChat QR scan

```bash
openclaw channels login --channel openclaw-weixin
```

Scan the QR code shown in the terminal with WeChat and confirm. Credentials are saved automatically to `~/.openclaw/openclaw-weixin/accounts/`. Repeat for each additional account.

## 5. Start the gateway and verify

```bash
openclaw gateway restart
openclaw channels status
curl -s -m 10 http://127.0.0.1:18789/health
```

A response containing `{"ok":true,...}` means healthy. The gateway listens on port `18789` by default.

## 6. Apply the patch (avoid duplicate replies)

By default the plugin dispatches inbound messages to its built-in agent. If you also poll and handle messages externally, both paths reply and the user gets duplicates. The patch makes the plugin write to the database without dispatching:

Locate the file (the hash suffix varies per install):

```bash
find ~/.openclaw/npm/projects -path "*openclaw-weixin/dist/src/messaging/process-message.js"
```

Back it up, then insert these three lines right after the message is written to the database and before the built-in agent is invoked:

```js
// PATCH: skip gateway agent dispatch entirely — messages are handled externally via quote_messages DB polling.
logger.info(`inbound dispatch skipped (external handler): peer=${ctx.To} accountId=${deps.accountId}`);
return;
```

In the tested environment these lines go after line 164 of the original file. Note: plugin upgrades or reinstalls overwrite the patch, so reapply after upgrading.

## 7. Deploy the scripts

```bash
mkdir -p ~/wechat-bridge
cp scripts/weixin-send.mjs scripts/weixin-send-image.mjs scripts/gateway-watchdog.sh ~/wechat-bridge/
chmod +x ~/wechat-bridge/gateway-watchdog.sh
```

Send a test message (replace with your own WeChat id):

```bash
node ~/wechat-bridge/weixin-send.mjs "bridge test" <your-wechat-id>
```

## 8. Set up scheduled tasks

Two tasks:

- **Watchdog**: run `gateway-watchdog.sh` every 2 minutes. It restarts a dead gateway automatically; only a failed restart needs a human. The watchdog reads the token from `~/.openclaw/.gateway-token` (generated by OpenClaw on first gateway start); adjust `TOKEN_FILE` in the script if your path differs.
- **Poller**: query the `quote_messages` table every 10 seconds, tracking the largest processed `created_at` in a watermark file. See the "Poll for inbound messages" section of `SKILL.md` for the SQL and the matching rules.

If your OpenClaw has a scheduler, create interval tasks directly; otherwise use system cron or a loop script. One rule matters above all: **keep exactly one inbound path**. Pick either the event hook or the poller, never both.

## 9. End-to-end verification

1. `curl` health check returns `{"ok":true}`
2. Send a test message with `weixin-send.mjs`; it arrives on WeChat
3. Reply from WeChat; a new row with `direction='inbound'` appears in `quote_messages`
4. Kill the gateway process manually; within 2 minutes the watchdog should restart it back to healthy

All four green means the bridge is live. See `SKILL.md` for day-to-day operation.

## Troubleshooting

- Plugin reports unsupported OpenClaw version: upgrade OpenClaw, then restart the gateway.
- Channel shows OK but not connected: confirm the plugin is enabled, restart the gateway, confirm QR login completed.
- Sends fail: the plugin install dir hash may change after upgrades; the scripts in this repo discover it automatically, no manual fix needed.
- Duplicate replies: check whether both the event hook and the poller are running; keep only one.
- Poller false positives: an empty `sqlite3 -json` result means no new messages. Do not acknowledge, do not touch the watermark file.
